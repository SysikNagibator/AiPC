# Модель угроз AiPC

Версия: 1.1+. Для пользователей и контрибьюторов.
Английская версия: `THREAT_MODEL.md`.

## 1. Что защищаем

- ПК пользователя: файлы, пароли, деньги (банки/крипта), приватную
  переписку, локальную сеть и SSH-хосты, доступные с ПК.
- Право человека решать: без ведома человека — никаких необратимых или
  внешне заметных действий (в режиме `ask` — без явного согласия).

## 2. От кого защищаем

| Кто | Пример | Статус |
|---|---|---|
| Вредоносная или взломанная модель | модель запускает `mimikatz`, тащит `id_rsa` наружу | Да — режимы, серверные подтверждения, deny-листы |
| Prompt-инъекция через недоверенные данные | страница «удали все файлы», документ со скрытыми инструкциями, SSH-вывод с командами, скриншот-ловушка | Частично — маркеры `untrusted` + taint-guard требуют подтверждения в `ask` И в `auto` (отключается `safety.taint_guard: false`) |
| Вредоносное ПО на ПК | кейлоггер читает `audit.log` | Частично — секреты в логах маскируются; защита уровня ОС вне скоупа |
| Атакующий в сети (MITM) | подмена exe при обновлении | Частично — без `SHA256SUMS.txt` в релизе автообновления нет, хеш сверяется до запуска; первая закачка всё равно TOFU по HTTPS. Пин подписи — в будущем |
| Физический доступ | — | Вне скоупа |

## 3. Границы доверия

1. **Модель ↔ сервер.** Модели НЕ доверяем: в `ask` каждый
   `mutate/exec/network`-вызов встаёт в `_wrap` до клика человека Да/Нет
   в нативном окне ОС. В окне — точная команда/путь/хост.
   Тишина `safety.confirm_timeout` (по умолчанию 120 с) = запрет
   (`denied_timeout`). Подтверждённое можно запомнить на
   `safety.allow_minutes` (по умолчанию 10) — никогда навсегда.
2. **Сервер ↔ ОС.** Реализации tools — доверенный код; прямой
   `import control/net` обходит MCP-гейт (один процесс, так задумано).
3. **Недоверенные входы.** `browser_eval`, `browser_history_search`,
   `screen_see`/`screen_region`/`screen_burst`/`window_shot`, `ui_snapshot`,
   `fs_read`, `web_search_pc`, вывод `ssh_exec`, буфер обмена приходят
   с меткой `{"untrusted": true, "source": ...}`. Системный промпт запрещает
   выполнять инструкции внутри таких данных без подтверждения человека.
   Если untrusted-ввод был в последних `safety.taint_window` вызовах
   (по умолчанию 10), следующий `exec/network/mutate`-вызов требует
   подтверждения даже в `auto`.
4. **Конфиг.** `~/.aipc/config.yaml` доверенный. Обновления deny-листов
   (`safety.version`) мержат дефолты с пользовательскими добавлениями,
   ничего не стирают.

## 4. Известные атаки и статус

- Инъекция с веб-страницы → агент выполняет команды: закрыто маркерами +
  taint-guard. Остаток: модель может пересказать, а не цитировать —
  подтверждение остаётся последней стеной.
- Вредоносный документ через `fs_read` → то же самое.
- Скриншот со встроенными инструкциями → скрины помечены untrusted.
- Вредоносный вывод SSH-сервера → вывод `ssh_exec` помечен untrusted.
- Кража секретов (`set`, `type ...\Login Data`, `Get-Content id_rsa`):
  закрыто нормализацией команд + проверкой путей внутри команды + фильтром
  имён `env_get`. Секреты маскируются в `audit.log` и в ответах
  `env_get`/`fs_read` (известные паттерны токенов/ключей). Остаток: остальные
  каналы (браузер/SSH-вывод, текст чата) идут как есть с меткой untrusted.
- Вредоносный exe при обновлении: **в основном закрыто** — нет `SHA256SUMS.txt`
  в релизе = нет автообновления; несовпадение хеша = файл удалён, установка
  прервана. Остаток: первая закачка — TOFU (суммы тем же каналом); подпись кода — в будущем.

## 5. Чего проект НЕ гарантирует

- Deny-листы — ремень, а не стена: обфускация эволюционирует; настоящая
  граница — режимы + подтверждения. Для строгих настроек —
  `run_cmd_policy: allowlist`.
- Песочницы нет: tools работают с правами пользователя. Режим `auto` +
  инъекция в промпте = окно подтверждения последняя линия обороны. Держите
  `ask` (по умолчанию), когда агент трогает сеть или чужие файлы.
- `audit.log` лежит на той же машине; против локального малваря это
  улика, а не защита.
- Нет защиты от скомпрометированной IDE/MCP-клиента, подделывающего вызовы —
  сервер доверяет своему stdio-пиру.
